## 本番公開（インターネット公開）前チェックリスト

> 2026-06-06 追記。アプリは「自宅サーバー + VPN/Tailscale 限定」を前提に設計されている。**インターネットに一般公開する場合**は前提が崩れるため、以下を上から順に対応する。詳細とリスク評価は [docs/security.md](security.md) が正本。

### 🔴 公開前に必須（未対応だと公開しない）

- [ ] **認証の追加** — 全 API が無認証。誰でも記録の閲覧/作成/削除/画像アップロードが可能。CORS は認証の代替にならない。対応候補：VPN/Tailscale 限定、リバースプロキシの Basic 認証、Cloudflare Tunnel + Access、アプリへの固定トークン認証のいずれか（security.md §1）
- [ ] **HTTPS/TLS 化** — frontend nginx は `listen 80` のみで TLS 終端がない。Caddy（自動 Let's Encrypt）か Cloudflare Tunnel で HTTPS を付与する
- [ ] **`CORS_ORIGIN` を prod に設定** — `docker-compose.prod.yml` の backend env に `CORS_ORIGIN` がなく、未設定だと全 Origin 許可（`Any`）にフォールバックする（`main.rs`）。本番ドメインを設定する（security.md §4）

### 🟡 公開前に推奨（中）

- [ ] **アップロード画像の内容検証** — 5MB 未満は再エンコードせず保存し「画像である」保証がない。常にデコード検証 or 再エンコード（security.md §2）
- [ ] **画像デコードの DoS/ブロッキング対策** — `resize_image` を `spawn_blocking` へ移し、デコード前に次元上限を設ける（security.md §3、`rust-backend.md` 規約）

### 🟢 運用面

- [x] **backend ヘルスチェック** — `/health` エンドポイント + compose healthcheck を追加済み（2026-06-06）
- [ ] **バックアップ戦略** — `pgdata` の DB ダンプと `uploads` ボリュームの定期バックアップ手順を定義する
- [ ] **Dockerfile の再現性** — backend の `rust:1-slim` を固定タグにする

## 優先タスク

### 1. Claude 実 API を少数サンプルで確認

`backend/.env` で `CLAUDE_API_KEY` を設定し、`CLAUDE_MOCK` を外して backend を再起動する。

確認対象：

- `dish_photo`：料理写真から概ね妥当な栄養値が返る
- `nutrition_label`：ラベルの印刷値を推定せず読み取る
- `text_ai`：料理名テキストから JSON が返る
- 失敗時に record は作成され、栄養値が `null` になる

実 API 呼び出しはコスト確認を兼ねて 1〜3 件から始める。
