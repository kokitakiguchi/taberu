# Taberu × Claude Code マルチエージェント運用戦略

最終更新：2026-06-05

Taberu で Claude Code のサブエージェントや worktree を使うときの方針です。MVP 機能は実装済みなので、今後は繰り返し作業の効率化やレビュー補助として小さく使います。

## 現状

- `.claude/` は `.gitignore` 対象で、リポジトリ追跡外のローカル AI 指示ドキュメントです。
- このローカル環境には `.claude/agents` と `.claude/rules` が存在します。
- ユーザーが明示した場合は `.claude/` も編集対象に含めます。ただし git では同期されません。
- カスタムサブエージェントは汎用的なレビュー、テスト、ドキュメント用途を中心に使います。

## 利用方針

### 1. 通常タスク

メインエージェントが直接進める。小さな修正、ドキュメント更新、単一領域のバグ修正はサブエージェント不要です。

### 2. レビューや調査

以下のような繰り返し観点はカスタムサブエージェントの候補です。

- コード品質レビュー
- セキュリティレビュー
- テスト観点の洗い出し
- ドキュメント同期チェック

### 3. 並行開発

Frontend と Backend を同時に大きく進める場合だけ、git worktree を検討します。DB migration が絡む場合は競合しやすいため、作業範囲を明確に分けます。

### 4. 学習トラック

MCP / Claude Skills / Agent SDK は、動作中のアプリを壊さない小さな検証から始めます。結果は [docs/learning-log.md](learning-log.md) に短く残します。

## 3 回ルール

同じ依頼や調査を 3 回以上手で繰り返したら、固定化を検討します。

候補：

- `record-doc-syncer`：API・DB・AI モデル変更と docs の差分チェック
- `migration-reviewer`：新規 migration と Rust 型、README の突き合わせ
- `food-vision-tester`：実 API サンプル確認用の手順整理

## 注意点

- `.claude/agents/*.md` はローカル管理です。別環境では手動配置が必要です。
- 機密情報、ユーザー画像、実 API 送信を扱う作業は、ユーザー確認を取ってから実行します。
- 複数エージェントに同じファイル編集を並行させない。
- 将来便利そうという理由だけで新しい agent を増やさない。
