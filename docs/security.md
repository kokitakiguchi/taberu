# セキュリティ メモ（運用・将来実装の注意点）

このファイルは Taberu を **インターネット公開 / 本番運用する前に必ず対応・検討すべきセキュリティ事項** をまとめたもの。
現在は開発中（ローカル・シングルユーザー前提）のため未実装の項目を含む。実装の正本はコードと `migrations/`。

> 最終レビュー日: 2026-06-05 / 対象コミット: `3bf8083`

## 前提

- 運用形態: シングルユーザー、`user_id = 1` 固定
- 想定デプロイ: 自宅サーバー（`docs/design.md` / `architecture.md` 参照）
- 自宅サーバーは他の家庭内機器と同一ネットワークにあることが多く、**アプリが侵害されると踏み台になり得る**点に注意する

---

## 対応済み（回帰させないこと）

これらは現状すでに実装されている。リファクタやリライト時に**壊さない**こと。

- **SQL インジェクション対策**: 全クエリを `sqlx::query!` / `query_as!` のパラメータ化で実装。文字列結合で SQL を組まない（`handlers/records.rs`, `handlers/stats.rs`）。
- **パストラバーサル対策（ファイル削除）**: `storage.rs` の `delete_file` で `canonicalize()` 後に `upload_dir` 配下か検証。保存ファイル名は UUID 生成でユーザー入力を使わない。
- **エラー情報の非漏洩**: DB / Storage / IO / Claude のエラーは内部詳細をログのみに記録し、クライアントには汎用メッセージを返す（`error.rs`）。
- **API キーの保護**: ハードコードなし・ログ出力なし。Claude API の宛先 URL はハードコード（`https://api.anthropic.com/v1/messages`）でユーザー入力から組み立てない。
- **ネットワーク分離**: `docker-compose.prod.yml` で backend は `expose` のみ・Postgres は非公開。外部公開は frontend のみ。
- **入力制限**: 画像 10MB 上限、`limit` の `clamp(1,200)`、日付フォーマット検証。

## 未実装 / 公開前に必須（優先度: 高）

### 1. 認証・認可がない（最重要）
全 API が無認証。到達できる人は誰でも全記録の閲覧・作成・削除・画像アップロードが可能。
- **CORS は認証の代替にならない**（サーバー間リクエストや `curl` には無力）。
- 対応候補（いずれか）:
  - インターネットに直接公開せず **VPN / Tailscale 経由** のみにする（最も簡単で堅実）
  - リバースプロキシ（nginx / Caddy）で **Basic 認証** または **mTLS**
  - アプリに最小限の固定トークン / セッション認証を実装
- 将来マルチユーザー化するなら `user_id = 1` 固定の解消とセッション管理が前提になる。

---

## 公開前に推奨（優先度: 中）

### 2. アップロード画像の内容検証
`storage.rs` のリサイズ（再エンコード）は 5MB 超のみ。**5MB 未満はバイト列をそのまま保存**し、拡張子だけ強制している。`detect_media_type` はファイル名・マジックバイトのみで、実際に画像としてデコードできるかは検証していない。`/uploads` は `ServeDir` で配信される。
- 現状リスクは低い（`ServeDir` は拡張子ベースで `Content-Type: image/*` を付与するためブラウザでの HTML 実行＝保存型 XSS は起きにくい）が、「画像である」保証がない。
- 対応候補: アップロード時に**サイズに関わらず一度デコード検証**する（または常に再エンコードして保存する）。

### 3. 画像デコードの DoS / 実行ブロッキング
- `resize_image` を `spawn_blocking` の外で実行しており、CPU バウンドな処理が async executor をブロックする（`rust-backend.md` の「画像エンコードは `spawn_blocking`」規約に未準拠）。
- `image` クレートでユーザー画像をデコードするため **decompression bomb**（小サイズ→巨大ピクセル）でのメモリ枯渇に注意。10MB 入力上限が一定の緩和になる。
- 対応候補: デコード/エンコードを `spawn_blocking` に移し、デコード前にピクセル上限（次元チェック）を設ける。

## 公開前に確認（優先度: 低）

### 4. CORS のデフォルト全開放
`main.rs` で `CORS_ORIGIN` 未設定時は `allow_origin(Any)` に警告ログのみでフォールバックする。認証がない現状では CORS 自体が防御線にならないが、本番では `CORS_ORIGIN` を必ず設定する。

### 5. フロントエンド依存の既知脆弱性
`react-router` 6.7.0–6.30.3 に open redirect（moderate, GHSA-2j2x-hqr9-3h42）。`cd frontend && npm audit fix` で解消可能。依存は定期的に `npm audit` で確認する。

### 6. レート制限がない
無認証と相まって、画像アップロード（Claude API コストに直結）を無制限に叩かれ得る。公開時はリバースプロキシ層でのレート制限を検討する。コスト面は `docs/cost-optimization.md` も参照。

---

## パブリックリポジトリ公開時の注意

- `.gitignore` で `.env` / `*.key` / `*.pem` / `uploads/` / `.claude/` を除外済み。**新しい機密ファイルを追加したら必ず `.gitignore` を更新**してからコミットする。
- 追跡してよいのは `*.env.example`（ダミー値のみ）。実際の API キー・DB パスワードは絶対にコミットしない。
- コミット前に `git diff --cached` で機密混入がないか確認する習慣をつける。
- 万一実キーをコミットしてしまったら、**履歴書き換えだけでなく当該キーのローテーション（無効化・再発行）** を行う（公開リポジトリは即座に収集される前提）。
