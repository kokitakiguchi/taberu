# 学習トラック運用ルール

## このプロジェクトの動機（再掲）

1. **最優先：動くプロダクト** — Phase 1 MVP の完成
2. **副次：コードの学習** — Rust / Axum / React の「読んで直せる」理解
3. **副次：AI 技術の実践** — MCP / Claude Skills / Agent SDK の体感

学習目的は **副次**。MVP を止めるなら学習を後回しにする。

## 学習行動を発動する条件

新しい技術（MCP, Skill, Agent SDK, 不慣れな crate など）に手を出すのは、以下を **すべて** 満たすとき：

- [ ] 該当する MVP 機能が **既に動いている**
- [ ] 別ブランチか別ディレクトリで試せる（main を壊さない）
- [ ] 1 〜 2 日以内で「動く or 諦める」判断ができそう

## 撤退判断（「これ以上は時間の無駄」のシグナル）

以下が起きたら学習トラックを一旦停止し、素の実装に戻る：

- 2 時間以上、原因不明のエラーで止まっている
- 公式ドキュメントの該当箇所が見つからない
- 学習目的の作業が MVP のスケジュールを **明確に** 遅らせている
- 「動かしてはいるが、何が起きているか説明できない」状態が続く

撤退するときは `docs/learning-log.md` に「何を試して、なぜ撤退したか」を 2 〜 3 行残す（将来の再挑戦のヒントになる）。

## 学習ログの書式

`docs/learning-log.md` を簡易ログとして使う。書式は自由だが目安：

```
## 2026-05-14 — Claude Vision の最初の呼び出し
- できたこと: base64 画像で JSON レスポンスが返った
- ハマった: 画像が大きいと 413。リサイズ実装が必要
- 次: image crate でリサイズ
```

エントリは短くて良い。**書かないより書く** ことが重要。

## 「学習目的だから」を言い訳にしない領域

以下はプロダクションの基本なので、学習目的でも省略しない：

- 機密情報のハードコード禁止
- `unwrap()` / `panic!` の濫用禁止（main 起動処理を除く）
- 入力バリデーション（特に外部入力）
- ユーザーに返すエラーレスポンスの形式統一

## エージェント側（Claude Code）の振る舞い

- ユーザーが「ちょっと試したい」と言ったら、まず **最小サンプル** を提案する
- 統合の前に「これで MVP は止まらないか」を確認してからコードを書く
- ハマっていそうなら、上記の撤退判断条件を提示してユーザーに判断を仰ぐ
- 学習トラックの作業を完了報告するときは「何を学んだか」を 1 行添える
